**总览**

* 目标：在美国服务器部署完整项目（前端、后端、验证服务），支持“生产验证”与“测试数据演示”两种模式，可一键切换。

* 云环境：AWS（推荐 us-east-1 或 us-west-2）。

* 部署方式：容器化（ECS Fargate）+ 静态前端（S3+CloudFront）+ 私网验证服务（`jp-verify`）。

**架构与组件**

* 前端：`apps/us-frontend` 构建后部署到 S3，CloudFront 全球分发，源在美国区。

* 后端：`apps/us-backend` 部署为 ECS Fargate Service，私网访问 `jp-verify`，对外暴露 API 网关 + ALB。

* 验证服务：`apps/jp-verify` 作为独立 ECS 服务，仅私网可见。

* 测试数据源：S3 存储 `liqpass-test-data`（美国区），提供 `/mock/*` 接口用作演示数据（订单详细与 evidence）。

**数据源模式**

* 生产验证：后端路由 `/api/v1/claims/prepare`、`/api/v1/claims/verify` → `jp-verify`；前端正常交互。

* 测试数据演示：后端路由 `/mock/orders/:id` 与 `/mock/evidence/:id/:file` 只读从 S3 回传；前端通过页面开关切换数据源。

**安全与合规**

* Secrets：AWS Secrets Manager+KMS 管理 `OKX_API_KEY/SECRET/PASSPHRASE/UID` 等，后端按需取用；前端不存放敏感信息。

* 网络：VPC 私网、子网分层、WAF 防护、TLS 强制、速率限制；`jp-verify` 不暴露公网。

* 观测：CloudWatch 日志与指标、ALB 访问日志、X-Ray（可选）链路追踪。

**部署步骤**

1. 容器与构建

   * Docker 化 `us-backend` 与 `jp-verify`；推送到 ECR。

   * 构建前端：`pnpm -C apps/us-frontend build`，产物上传至 S3。
2. 基础设施

   * 创建 VPC、子网、Internet/NAT 网关，配置安全组与 IAM 角色。

   * 创建 ECS Fargate 集群与两个 Service（`us-backend`、`jp-verify`）。

   * 配置 ALB（公网）与私网 Target Group；API Gateway（可选）前置。

   * 配置 CloudFront 分发前端 S3 源，开启 HTTPS。
3. 测试数据上载

   * 将以下文件/目录上传 S3（保留层级）：

     * `orders/order_2938801601245126656_detailed_report.json`

     * `orders/order_2940071038556348417_detailed_report.json`

     * `reports/order_2938801601245126656_detailed_report.json`

     * `reports/order_2940071038556348417_detailed_report.json`

     * `reports/evidence/<id>/{bills.json,fills.json,index.json,instrument.json,merkle.json,meta.json,order.json,summary.json,verification_summary.csv}`
4. 后端配置

   * 环境变量：`JP_VERIFY_URL=http://jp-verify:8080`, `MOCK_DATA_SOURCE=true|false`, `S3_BUCKET=liqpass-test-data`, `AWS_REGION=us-east-1`。

   * 新增 `/mock/*` 路由只读 S3；`claimsService.verifyClaim` 支持 `dataSource` 混合。
5. 前端配置

   * 环境变量：`VITE_API_BASE=https://api.us.liqpass.example`。

   * 页面增加“数据源”切换（生产/测试），测试模式调用 `/mock/*`，复用现有 JSON 视图。
6. 验证与演示

   * ApiSettings：输入 API 信息，点“验证”（生产模式）；切换到测试模式，用您提供的订单号演示 JSON 回显与 evidence 展示。

   * ClaimsManage/ClaimsPage：输入订单号→验证→展示风险与清算信息；完整演示赔付流程（测试模式可模拟）。

**运维要点**

* IAM 最小权限：后端仅对指定 S3 Bucket 拥有只读权限；Secrets 细粒度授权。

* 速率限制与告警：API Gateway/WAF，CloudWatch 告警（错误率/延迟/5xx）。

* 灰度与回滚：ECS 任务版本化与最小健康容器数，前端多版本保留。
