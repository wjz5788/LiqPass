# 赔付管理验证后端架构详细文档

## 概述

LiqPass项目的赔付管理验证系统采用微服务架构，核心由两个服务组成：
- **us-backend**: 主要的业务逻辑服务，处理赔付申请、验证流程管理
- **jp-verify**: 专门的交易所订单验证服务，负责从OKX等交易所获取订单数据并生成验证证据

## 系统架构

### 服务依赖关系
```
us-backend (端口: 3000/8080)
    ↓ 调用
jp-verify (端口: 8082)
    ↓ 调用
OKX交易所API
```

### 核心组件

#### 1. jp-verify服务
- **技术栈**: Python + FastAPI
- **主要功能**: 
  - 交易所API集成（OKX）
  - 订单数据获取和验证
  - JCS规范化JSON处理
  - 证据生成和存储
  - API密钥安全验证

**健康检查端点**:
```bash
# 基础健康检查
curl http://127.0.0.1:8082/healthz

# 预期响应
{
  "status": "healthy",
  "service": "jp-verify",
  "timestamp": "2024-01-01T00:00:00.000Z"
}
```

**主要API端点**:
- `POST /api/verify` - 标准验证接口
- `POST /api/verify/standard` - 标准化验证接口

#### 2. us-backend服务
- **技术栈**: Node.js + Express + TypeScript
- **主要功能**:
  - 赔付申请管理
  - 验证流程协调
  - 证据存储和管理
  - 用户权限控制
  - 链上事件监听

## 赔付验证流程

### 1. 创建赔付申请
```typescript
// 用户提交赔付申请
POST /api/v1/claims
{
  "orderId": "order_123",
  "claimType": "liquidation",
  "amountUSDC": 100,
  "description": "爆仓赔付申请",
  "evidenceFiles": []
}
```

### 2. 验证流程触发
当用户触发验证时，系统执行以下步骤：

#### 步骤1: 准备验证
```typescript
// ClaimsService.prepareClaimVerification()
const { claimToken, claimId } = await claimsService.prepareClaimVerification(
  orderId, 
  userId
);
```

#### 步骤2: 执行验证
```typescript
// ClaimsService.verifyClaim()
const result = await claimsService.verifyClaim(
  orderId,
  orderRef,
  claimToken,
  userId
);
```

#### 步骤3: 调用jp-verify服务
```typescript
// jpVerifyClient.verifyStandard()
const response = await jpVerifyClient.verifyStandard({
  exchange: 'okx',
  ordId: resolvedOrderRef,
  instId: 'BTC-USDT-SWAP',
  keyMode: 'inline',
  apiKey: decrypted.api_key,
  secretKey: decrypted.secret,
  passphrase: decrypted.passphrase,
  clientMeta: { source: 'claims', requestId: uuid() }
}, 45000);
```

### 3. 验证结果处理
jp-verify返回的数据结构：
```json
{
  "isLiquidated": true,
  "instId": "BTC-USDT-SWAP",
  "closeTime": "2024-01-01T00:00:00.000Z",
  "normalized": {
    "data": { /* 规范化数据 */ },
    "canonical_json": "{/* JCS格式JSON */}",
    "evidence_root": "0x..." /* Keccak256哈希 */
  },
  "verifyStatus": "PASS"
}
```

## 错误处理和诊断

### 常见错误类型

#### 1. 连接错误
```
AxiosError: connect ECONNREFUSED 127.0.0.1:8082
```
**原因**: jp-verify服务未启动或端口错误
**解决**: 
1. 检查jp-verify服务状态
2. 确认端口配置正确
3. 查看jp-verify服务日志

#### 2. DNS解析错误
```
getaddrinfo ENOTFOUND xxx
```
**原因**: JP_VERIFY_BASE_URL配置错误
**解决**: 检查环境变量中的URL配置

#### 3. 验证失败错误
```json
{
  "status": "failed",
  "error": "订单未找到或无效"
}
```
**原因**: 订单信息不匹配或API密钥无效
**解决**: 
1. 检查订单号是否正确
2. 验证API密钥配置
3. 确认交易所账户权限

## 安全机制

### API密钥安全
1. **加密存储**: 所有API密钥使用AES-256-GCM加密
2. **传输安全**: HTTPS加密传输（生产环境）
3. **访问控制**: 基于用户ID的权限验证
4. **频率限制**: 每分钟60次，每小时1000次

### 数据验证
1. **输入验证**: Zod模式验证所有输入
2. **权限检查**: 用户只能访问自己的订单和赔付申请
3. **状态机**: 严格的状态转移规则
4. **审计日志**: 所有关键操作记录审计日志

### 证据完整性
1. **JCS规范化**: 使用RFC 8785标准进行JSON规范化
2. **哈希验证**: Keccak256哈希确保数据完整性
3. **证据链**: 每个验证步骤生成可追溯的证据
4. **防篡改**: 证据一旦生成不可修改

## 性能优化

### 缓存策略
1. **验证结果缓存**: 相同订单验证结果缓存5分钟
2. **API响应缓存**: 交易所API响应适当缓存
3. **数据库查询优化**: 关键字段建立索引

### 异步处理

## 部署指南

### 开发环境部署
```bash
# 启动jp-verify服务
cd apps/jp-verify
pip install -r requirements.txt
python main.py

# 启动us-backend服务
cd apps/us-backend
npm install
npm run dev
```

### 生产环境部署
```bash
# 使用PM2管理服务
pm2 start apps/jp-verify/main.py --name jp-verify
pm2 start apps/us-backend/dist/index.js --name us-backend

# 设置环境变量
echo "JP_VERIFY_BASE_URL=http://localhost:8082" >> .env
echo "JP_VERIFY_TEST_MODE=0" >> .env
```

## 故障排除

### 服务无法连接
1. 检查防火墙设置
2. 确认端口未被占用
3. 验证网络连通性
4. 查看服务启动日志

### 验证总是失败
1. 检查API密钥权限
2. 确认交易所账户状态
3. 验证订单信息准确性
4. 检查网络代理设置

### 性能问题
1. 监控CPU和内存使用
2. 检查数据库查询性能
3. 优化缓存策略
4. 考虑负载均衡
